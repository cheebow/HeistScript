# Phase 8 結果: ビジュアル・UI/UX のブラッシュアップ（2026-10-27）

## 実装した内容

| 項目 | 実装 |
|---|---|
| ズーム | 「表示」メニューで 1x〜4x の手動倍率と自動（領域に収まる最大倍率）。領域より大きい倍率はスクロールでパン。整数倍率のみ |
| 自動レイアウト | 自動倍率のとき、マップを 2x で表示できる幅があればエディタ幅を自動で詰める（エディタ幅を手動で変えた後は行わない）。下部パネルの初期高さは画面高の 26%（160〜300px） |
| 識別性 | 怪盗が2人以上のときマップ上に名前タグ（怪盗A/怪盗B）。選択中はタグ強調 + 白枠 |
| オーバーレイ | 警備員の視界／カメラの視界／移動予定の経路を個別に ON/OFF。設定は保存 |
| コード⇄マップ | マップ上の怪盗クリックでエディタのタブも切替。実行前でも状態パネルに初期状態を表示 |
| 重要イベント | ログフィルタ「重要」（発見・逮捕・気絶・取得・警報・シグナル・ハンドラ・エラー等）。ログ行クリックでその tick へ移動。過去のコマ表示中は先の行を薄く表示 |
| 失敗原因 | 結果画面に「発生 tick」「関係者」を表示し、「その直前から見る」で 5 tick 前へ移動して該当怪盗を選択 |
| パネル | 下部パネルの高さをドラッグ変更、最小化／復元 |
| 演出 | 実行開始時の「作戦開始」バナー。「演出を減らす」設定で tick 連動の演出をすべて省略（状態マークは残す） |
| 保存 | `settings.showCameraVision / showPaths / reducedMotion / zoom` を追加（欠けていれば既定値。schemaVersion 据え置き） |

コア（`src/core`）は無変更。オーバーレイ・ズーム・パネル操作は描画層のみで、tick・経路探索・結果に影響しない（E2E で確認）。

## 確認した制約

- 1280×720 では Stage 5（24×14 タイル = 768×448px）が下部パネルと同時には収まらないため、下部パネルを最小化すると収まる（E2E で確認）。より小さい画面では横スクロールでパンする。
- 1920×1080 では自動倍率は 1x（2x には横幅 1536px が必要で、エディタ最小幅 360px と両立しない）。手動で 2x を選ぶとスクロール表示。16〜20 タイル幅のステージは自動で 2x になる。

- 下部パネルの各列（ログ／状態／ヒント）の幅は固定。
